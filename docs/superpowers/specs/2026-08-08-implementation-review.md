# 実装レビュー (2026-08-08)

ローカルに rustfs (S3互換) を立て、開設 → ログイン → 各画面の操作を実際に通して、
`docs/design/Mofune Mobile.dc.html` の 2b と突き合わせた結果。

環境: `docker run -p 9333:9000 rustfs/rustfs server /data`、バケット `mofune`、
CORS は GET/PUT/HEAD/DELETE、バケットポリシーで匿名 GET を許可、アプリは `vite --port 5199`。

## A. 機能の欠陥 (見た目より先に直すもの)

### A1. 担当者・管理者がお知らせを投稿できない ★最優先

管理者でログインしてお知らせを送ると「オフラインのため送信待ちにしました」と出て、
永久にキューに残る。オフラインではない。

原因: ログイン後にセッションが持つストレージは `HttpStorageProvider` で、これは
**読み取り専用**(`put` は `UnsupportedOperationError`)。`ComposeView` はここへ
`flushOutbox` するので必ず失敗する。書き込みには `settings/storage.enc` から
資格情報を読んで `S3StorageProvider` を作る必要があり、それをしているのは
`StaffPanelView` だけ。

つまり **Phase 2b「メッセージの投稿」は画面上で一度も成立していない**。単体テストは
`MemoryStorageProvider`(書き込み可)を渡していたので気づけなかった。

### A2. 参加者が「れんらく」を送れない場合がある / 担当者は常に送れない

`AbsenceView` は inbox grant を必須にしているが、grant は参加者にしか配られない
(`publishGrants` が `role !== 'member'` を除外)。担当者・管理者は「いまは送信できません」
のまま。要件書 §3 は不在連絡を全ロールが行えると定めている。

担当者は書き込み資格情報を持つので、grant ではなく直接書けばよい。

### A3. お知らせに添付を付けられない

`ComposeView` は `attachments` を持っているが、**ファイルを選ぶ UI が無い**ので常に空。
デザイン 06 は「写真を添付 / PDFを添付」。閲覧側 (`MessageDetailView`) は実装済みなので、
投稿側だけが欠けている。

### A4. 接続コードが紙で配れない

実測 **310 文字の base64**。デザイン 01 は `mofu-3KQ7-A8` の短いコードと
「QRコードを読み取る」。310 文字は手入力が現実的でなく、QR も未実装。
このままでは参加者に配れない。

## B. 画面構成のズレ

| # | デザイン | 実装 |
|---|---|---|
| B1 | タイムラインは最上部にグループのヘッダ | 操作ボタン4つがヘッダの**上**に積まれている |
| B2 | 各画面に上部バー(「← お知らせ」「キャンセル / お知らせを作る / 下書き」) | 上部バーが無く、戻るは本文中のボタン |
| B3 | ボトムナビは画面下端に固定 | 内容が短いと本文直下に浮く |
| B4 | 選択肢はチップ(丸い枠)の集合 | `fieldset` がブラウザ既定の枠線のまま |
| B5 | 選んだ種類・理由が塗りつぶしで分かる | `aria-pressed` はあるが見た目が変わらない |
| B6 | お知らせ作成に画面名と宛先の人数 | 画面名が無い。宛先はチェックボックスのみ |
| B7 | タイムラインにタブ(すべて/未読/要回答)と同期状態 | どちらも無い |
| B8 | 設定はカード + chevron + トグル | 見出しとボタンが平置き |

## 反省

単体テストが全部 `MemoryStorageProvider` を使っていたため、**読み取り専用プロバイダで
書き込もうとする経路**が誰にも検査されていなかった。テストダブルが本番より寛容だと、
本番だけで落ちる。以後、書き込み経路のテストには「読み取り専用プロバイダを渡すと
どうなるか」を1本入れる。
