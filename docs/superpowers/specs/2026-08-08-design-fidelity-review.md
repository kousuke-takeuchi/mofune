# デザイン忠実度の再レビュー (2026-08-08)

原稿 (`docs/design/Mofune Site.dc.html` の 1b、`Mofune Mobile.dc.html` の 2a / 2b) を
ブラウザで描画し、実装と1画面ずつ突き合わせた結果。

**結論: スマホのランディングページは合っている。PC のランディングページとアプリ画面は
まだ離れている。** とくにアプリは「部品の見た目」ではなく「情報の構造」が違う箇所がある。

## 直す順番の案

1. **表題 (D1 / E1 / G2)** — 唯一のデータ構造の変更。`MessageContent.title` を足す。
   これが入らないとタイムラインも詳細も原稿の形にならない
2. **添付のサムネイル (D2)** — 端末に控えた画像を出す。既に IndexedDB にある
3. **主ボタンの色をテラコッタへ統一 (B1 / E5)** と**下端固定のボタン (C4 / F3 / G5)**
4. **PC の A1 / A2 / A3 / A4 / A5** — ランディングページの作り直し
5. 残りの細部 (バッジ・チップ・アイコン)

## 直した結果 (2026-08-08)

上の表のうち、次を実装した。

- **A1–A9** ランディングページ (PC): 筐体入りのヒーロー、2×2 のできること、
  暗色パネルの HOW IT WORKS、画面幅いっぱいの SECURITY 帯 (中央の保管場所は緑)、
  マスコット付きの締めの CTA、中央寄せの WHY、サンド地のはじめかた、
  見出し行の右に置いた導入文
- **B1 / B2** 主ボタンのテラコッタ、パスワードの「表示」切替 (ログインと再開の両方)
- **C1–C4** 3分割の進捗バーと 2 / 3 の表示、クリーム地の確認カード、
  プライバシーポリシーの同意チェック、下端に貼り付く登録ボタン
- **D1–D7** 表題、添付のサムネイル (3枚 + 残り枚数)、要回答バッジとカード内の回答ボタン、
  同期済みチップと所属の副題、暗色のタブ、アイコン付きの下ナビ、行頭の未読の点
- **E1–E5** 表題、「Aチーム・8/7 9:12・田中 みか(担当)」のメタ行、ラジオ行の回答、
  質問の右に置いた締切
- **F1–F3** 今日・明日の日付チップ、暗色の「種類」チップ、下端固定の送信
- **G1–G5** 人数付きの宛先チップ、表題の入力欄、写真とPDFの2ボタン、
  出欠・選択式・記述式の種類チップ、下端固定の「送信して通知する」

記述式は表示だけでなく仕組みも足した。`FormDefinition.kind` を任意項目として増やし
(古いお知らせは出欠として読む)、記述式では選択肢を持たず、書いた内容が答えになる。

## 直さないもの

- B4 接続コードの短縮 — QR で配る方針にしたため。原稿の短いコードは、別途
  「短い符号 → 接続情報」を引く仕組みが要る(中央サーバーが無いので置けない)
- ~~B3 QR の読み取り~~ — 2026-08-08 に実装。`BarcodeDetector` は iOS に無いので
  読み取り器 (jsqr) を同梱した。ひとりぶんの情報を載せた QR なら1回読むだけで入る
- 原稿 07 / 08 / 09 / 11 / 12 の細部 — 実装済み機能に対する画面は用意したが、
  原稿の作り込み(アバター一覧・統計の帯など)には合わせていない
